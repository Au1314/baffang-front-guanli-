# 通知模块实现方案

## 1. 方案概述

根据需求，在现有项目基础上新增通知模块，实现查询通知列表功能。通知模块将包括API服务、路由配置、视图组件和相应的权限控制。

## 2. 实现步骤

### 2.1 API服务层

* 在 `src/api/index.js` 中添加通知相关API请求

* 新增 `getNoticeList` 方法，用于查询通知列表，支持参数：type、userId、isRead、keyword、page、pageSize

* 新增 `markNoticeAsRead` 方法，用于标记通知为已读

* 新增 `deleteNotice` 方法，用于删除通知

### 2.2 路由配置

* 在 `src/router/index.js` 中添加通知模块路由

* 新增通知模块主路由 `/notice`

* 新增通知列表子路由 `/notice/list`

* 配置路由元信息，包括标题和权限控制

### 2.3 视图组件

* 创建 `src/views/Notice.vue` 作为通知模块主视图

* 创建 `src/views/NoticeList.vue` 作为通知列表视图

* 通知列表视图包含：

  * 筛选条件（通知类型、接收用户、是否已读、关键词搜索）

  * 分页控件

  * 通知列表表格

  * 通知操作按钮（标记已读、删除）

### 2.4 数据模型

* 根据API响应格式定义通知数据模型

* 包含字段：id、userId、userName、title、content、type、typeName、relatedId、relatedType、relatedTypeName、isRead、createTime、readTime

### 2.5 权限控制

* 根据现有项目权限体系，配置通知模块的访问权限

* 支持超级管理员和普通管理员角色访问

## 3. 技术实现细节

### 3.1 API服务实现

```javascript
// 在auth.js中添加通知相关API
export const authApi = {
  // ... 现有API
  
  // 通知管理相关API
  getNoticeList(params) {
    return request.get('/notice/list', { params })
  },
  markNoticeAsRead(noticeId) {
    return request.put(`/notice/${noticeId}/read`)
  },
  deleteNotice(noticeId) {
    return request.delete(`/notice/${noticeId}`)
  }
}
```

### 3.2 路由配置实现

```javascript
// 在router/index.js中添加通知路由
{
  path: '/notice',
  name: 'Notice',
  component: () => import('@/views/Notice.vue'),
  meta: {
    requiresAuth: true,
    title: '通知管理',
    hideLayout: false,
    permission: ['超级管理员', '普通管理员']
  },
  children: [
    {
      path: 'list',
      name: 'NoticeList',
      component: () => import('@/views/NoticeList.vue'),
      meta: {
        title: '通知列表'
      }
    }
  ]
}
```

### 3.3 视图组件实现

* `Notice.vue`：使用MainLayout布局，包含子路由出口

* `NoticeList.vue`：

  * 使用Element Plus的Table组件展示通知列表

  * 使用Form组件实现筛选条件

  * 使用Pagination组件实现分页

  * 实现通知类型、是否已读等状态的文字转换

  * 实现批量操作功能

### 3.4 数据处理

* 实现通知类型映射：0-系统公告，1-充电通知，2-预约通知，3-V2V通知，4-紧急呼叫通知，5-订单通知，6-审核通知

* 实现是否已读状态映射：0-未读，1-已读

* 实现关联业务类型映射
