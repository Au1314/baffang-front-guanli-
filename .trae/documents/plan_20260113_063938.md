# 快速分析功能错误处理优化方案

## 问题分析
1. **后端错误**：数据库中缺少 `charge_rate` 表，导致 SQL 查询失败
2. **前端表现**：请求超时，显示通用错误信息，用户体验不佳
3. **根本原因**：前端请求超时时间过短，后端异常处理不及时

## 解决方案

### 1. 优化前端错误处理机制
- 改进 `QuickAnalysis.vue` 中的错误处理逻辑
- 增加请求超时时间
- 显示更友好的错误信息

### 2. 具体实现步骤

#### 步骤1：调整API请求超时时间
在 `api/index.js` 中增加请求超时时间，从当前的10秒调整为30秒，给后端足够的处理时间：
```javascript
const service = axios.create({
  baseURL: '/api/v1/admin',
  timeout: 30000, // 从10000改为30000
  headers: {
    'Content-Type': 'application/json'
  }
})
```

#### 步骤2：改进错误处理逻辑
在 `QuickAnalysis.vue` 中优化 `handleAnalysis` 方法，增加更详细的错误信息：
```javascript
const handleAnalysis = async () => {
  if (!question.value.trim()) {
    ElMessage.warning('请输入要分析的问题')
    return
  }
  
  loading.value = true
  try {
    const result = await authApi.quickAnalysis(question.value.trim())
    analysisResult.value = result.data
    ElMessage.success('分析完成')
  } catch (error) {
    console.error('分析失败:', error)
    // 更详细的错误信息
    let errorMsg = '分析失败，请稍后重试'
    if (error.code === 'ECONNABORTED') {
      errorMsg = '分析请求超时，请稍后重试'
    } else if (error.response?.data?.message) {
      errorMsg = error.response.data.message
    }
    ElMessage.error(errorMsg)
  } finally {
    loading.value = false
  }
}
```

#### 步骤3：增加后端错误信息传递
确保后端在发生异常时，返回明确的错误信息，而不是让请求超时

#### 步骤4：优化用户体验
- 在分析过程中显示更明确的加载状态
- 增加取消请求的功能
- 提供重试机制

## 预期效果
1. 延长请求超时时间，减少因后端处理时间长导致的超时错误
2. 显示更友好、更具体的错误信息，让用户了解问题所在
3. 改进错误处理逻辑，提升用户体验
4. 前端能正确处理各种后端错误情况

## 技术要点
- Vue 3 组合式 API
- Axios 请求超时配置
- 详细的错误信息处理
- 用户友好的错误提示

## 优势
- 提升系统的健壮性，能更好地处理后端异常
- 改善用户体验，提供更明确的反馈
- 便于开发人员调试和定位问题
- 保持代码的可维护性和扩展性
