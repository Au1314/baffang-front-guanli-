## 问题分析
1. **现象**：生成邀请码时报403 Forbidden错误
2. **根本原因**：API路径重复导致
   - 前端：`index.js` 中 axios 实例的 `baseURL` 已设置为 `/api/v1/admin`
   - 前端：`auth.js` 中生成邀请码的 API 路径又添加了 `/auth/invite-code/generate`
   - 最终请求 URL：`/api/v1/admin/auth/invite-code/generate`
   - 后端：可能期望的路径是 `/api/v1/admin/invite-code/generate`（没有 `/auth` 前缀）
   - 其他邀请码相关 API（如 `updateInviteCodeStatus`）的路径没有 `/auth` 前缀，与生成邀请码的 API 路径不一致

3. **路径不一致问题**：
   - 生成邀请码：`/auth/invite-code/generate`（有 `/auth` 前缀）
   - 更新邀请码状态：`/invite-code/{codeId}/status`（没有 `/auth` 前缀）
   - 删除邀请码：`/invite-code/{codeId}`（没有 `/auth` 前缀）
   - 批量删除邀请码：`/invite-code/batch`（没有 `/auth` 前缀）

## 修复方案
1. **修复 API 路径重复问题**：
   - 修改 `auth.js` 中生成邀请码的 API 路径，移除 `/auth` 前缀
   - 确保所有邀请码相关 API 路径格式一致

2. **统一邀请码 API 路径**：
   - `generateInviteCode`：`/invite-code/generate`（移除 `/auth` 前缀）
   - `getInviteCodeList`：`/invite-code/list`（移除 `/auth` 前缀）
   - 保持其他邀请码 API 路径不变

3. **优化 API 调用逻辑**：
   - 确保所有 API 路径格式一致
   - 添加详细的日志，便于调试
   - 完善错误处理

## 预期效果
- 生成邀请码的 API 路径不再重复
- 所有邀请码相关 API 路径格式一致
- 后端能正确识别和处理生成邀请码的请求
- 生成邀请码功能恢复正常
- 提高代码的一致性和可维护性
