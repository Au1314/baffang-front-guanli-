# 修复AI风险评估API请求403错误

## 1. 问题分析

### 1.1 错误原因

* **请求路径重复**：从错误信息可以看到，实际请求的URL是 `http://localhost:8080/api/v1/admin//ai/decision/risk/assess`，其中包含了两个连续的斜杠

* **路径拼接问题**：baseURL `/api/v1/admin` 与API路径 `/ai/decision/risk/assess` 拼接时，由于两者都包含斜杠，导致生成了重复斜杠的URL

### 1.2 其他可能因素

* 后端API权限配置问题

* API路径格式与后端要求不一致

## 2. 修复方案

### 2.1 推荐方案

保持现有baseURL配置不变，仅修正AI风险评估的API路径格式，确保路径拼接后不会出现重复斜杠。

## 3. 修复步骤

### 3.1 第一步：修正AI风险评估API路径

在 `src/api/auth.js` 中修正 `riskAssessment` 方法的请求路径，去掉路径开头的斜杠：

```javascript
// 当前错误路径
riskAssessment(params) {
  return request.post('/ai/decision/risk/assess', params, {
    timeout: 180000 // 3分钟超时
  })
}

// 修正后的路径
riskAssessment(params) {
  return request.post('ai/decision/risk/assess', params, {
    timeout: 180000 // 3分钟超时
  })
}
```

### 3.2 第二步：验证修复结果

* 重新启动开发服务器

* 访问AI风险评估页面

* 提交评估请求，验证是否返回200状态码

## 4. 预期效果

* API请求返回200状态码

* 成功获取风险评估结果

* 页面正常显示评估结果

* 控制台不再出现403错误

## 5. 技术要点

* 确保API路径格式正确，避免与baseURL拼接时出现重复斜杠

* 与后端API文档保持一致

* 注意axios的路径拼接规则
