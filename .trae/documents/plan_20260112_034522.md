# 重写获取待响应呼叫列表函数方案

## 1. 需求分析
- API请求参数：前4个参数（pageNum, pageSize, longitude, latitude）必须上传，后2个参数（type, maxDistance）可选
- API响应数据结构：包含total、pages、pageNum、pageSize和list字段
- 需要按照距离排序显示待响应呼叫列表

## 2. 实现步骤

### 2.1 修改 `fetchPendingEmergencyList` 函数
- 位置：`Emergency.vue` 中的 `fetchPendingEmergencyList` 函数
- 功能：调用 API 获取待响应呼叫列表，并按照距离排序
- 实现：
  ```javascript
  const fetchPendingEmergencyList = async () => {
    try {
      emergencyListLoading.value = true
      
      if (!currentLocation.value) {
        getCurrentLocation()
        return
      }
      
      // 构建请求参数，前4个参数必须传
      const params = {
        pageNum: 1,
        pageSize: 10,
        longitude: currentLocation.value.longitude,
        latitude: currentLocation.value.latitude
      }
      
      // 可选参数：type只有在有值时才传递
      if (emergencyFilter.type !== null && emergencyFilter.type !== undefined) {
        params.type = emergencyFilter.type
      }
      
      // 可选参数：maxDistance只有在有值时才传递
      if (emergencyFilter.maxDistance !== null && emergencyFilter.maxDistance !== undefined) {
        params.maxDistance = emergencyFilter.maxDistance
      }
      
      const response = await authApi.getPendingEmergencyCalls(params)
      
      // 优化数据处理逻辑，适应新的响应数据结构
      let listData = []
      if (response && response.code === 200 && response.data) {
        listData = response.data.list || []
        // 按照distance字段升序排序
        listData.sort((a, b) => a.distance - b.distance)
      } else {
        console.error('API响应格式错误或状态码非200')
      }
      
      // 更新列表数据
      pendingEmergencyList.value = listData
      
    } catch (error) {
      console.error('获取待处理紧急呼叫列表失败:', error)
      ElMessage.error('获取待处理紧急呼叫列表失败')
      pendingEmergencyList.value = []
    } finally {
      emergencyListLoading.value = false
    }
  };
  ```

### 2.2 验证 API 方法定义
- 已确认 `getPendingEmergencyCalls` 方法在 `auth.js` 中定义，路径为 `/emergency/call/pending`
- 无需额外添加 API 方法

### 2.3 优化响应数据处理
- 确保正确解析响应数据，只处理 `code === 200` 的成功响应
- 从 `response.data.list` 中提取列表数据
- 按照 `distance` 字段升序排序，确保最近的呼叫显示在最前面

### 2.4 保持错误处理逻辑
- 保留现有的完善错误处理逻辑
- 确保在错误情况下列表显示为空，避免显示错误数据
