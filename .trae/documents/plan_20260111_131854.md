# 实现帖子举报和评论举报分开管理的方案

## 一、需求分析
1. 当前论坛管理下的举报管理页面将帖子举报和评论举报混合在一起，通过筛选器区分
2. 用户希望将帖子举报管理和评论举报管理完全分开，不要放在一起
3. 保持现有的功能和样式不变，只是将它们拆分为两个独立的管理入口

## 二、实现方案

### 1. 修改论坛管理页面的举报管理结构
- 在论坛管理页面的举报管理标签页下，添加两个子标签页：帖子举报和评论举报
- 每个子标签页有自己的筛选条件、列表和分页控件
- 分别调用不同的API获取数据

### 2. 保持数据和逻辑分离
- 为帖子举报和评论举报分别创建独立的数据管理变量
- 保持现有的筛选条件和分页逻辑，但为每个类型创建独立的变量
- 分别实现获取帖子举报列表和评论举报列表的方法

## 三、具体实现步骤

### 步骤3：实现独立的获取列表方法
```javascript
// 获取帖子举报列表
const fetchPostReportList = async () => {
  try {
    postReportLoading.value = true
    const params = {
      pageNum: postReportPage.value,
      pageSize: postReportPageSize.value,
      keyword: postReportFilter.keyword,
      status: postReportFilter.status,
      priority: postReportFilter.priority,
      startTime: postReportFilter.startTime,
      endTime: postReportFilter.endTime
    }
    const response = await authApi.getPostReportList(params)
    postReportList.value = response?.list || []
    postReportTotal.value = response?.total || 0
  } catch (error) {
    // 错误处理
  } finally {
    postReportLoading.value = false
  }
}

// 获取评论举报列表
```

## 四、预期效果
1. 论坛管理页面的举报管理标签页下，将显示两个子标签页：帖子举报和评论举报
2. 每个子标签页有自己独立的筛选条件、列表和分页控件
3. 帖子举报子标签页调用帖子举报API，评论举报子标签页调用评论举报API
4. 保持现有的功能和样式不变，只是将它们拆分为两个独立的管理入口
5. 支持各自的筛选、分页、详情查看和审核操作

## 五、注意事项
1. 确保每个举报类型的数据和逻辑完全独立，避免相互影响
2. 保持UI样式的一致性，确保用户体验良好
3. 确保现有功能不受影响，特别是审核操作和详情查看
4. 确保API调用参数正确，分别调用对应的API接口
