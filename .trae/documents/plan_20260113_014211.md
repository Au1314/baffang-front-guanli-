# 修复通知详情功能错误

## 问题分析

从错误信息和截图可以看出：

1. **获取通知详情成功**：API响应返回了200 OK，通知详情数据正确返回
2. **标记已读失败**：调用 `/notice/{id}/read` API时返回403 Forbidden错误
3. **错误影响**：由于标记已读操作失败，导致整个`getNoticeDetail`方法被视为失败，显示"获取通知详情失败"的错误提示

## 根本原因

1. `getNoticeDetail`方法中包含了标记已读的逻辑
2. 调用标记已读API返回403错误
3. 用户明确表示管理端不需要实现阅读后标记已读功能

## 解决方案

### 1. 移除标记已读逻辑

从`getNoticeDetail`方法中移除所有标记已读的代码，包括：
- 调用`authApi.markNoticeAsRead(noticeId)`的API请求
- 相关的错误处理
- 本地列表状态更新

### 2. 简化代码逻辑

修改`getNoticeDetail`方法，只保留获取通知详情的核心逻辑，确保即使标记已读API不存在或返回错误，也不会影响通知详情的显示。

### 3. 代码修改

修改`getNoticeDetail`方法，移除标记已读的逻辑：

```javascript
// 获取通知详情
const getNoticeDetail = async (noticeId) => {
  detailLoading.value = true
  try {
    const response = await authApi.getNoticeDetail(noticeId)
    noticeDetail.value = response
    detailVisible.value = true
  } catch (error) {
    ElMessage.error('获取通知详情失败')
    console.error('获取通知详情失败:', error)
  } finally {
    detailLoading.value = false
  }
}
```

### 4. 其他优化

- 确保获取详情的try-catch块只处理获取详情的错误
- 移除不再需要的相关代码
- 简化逻辑，提高代码可读性

## 预期效果

1. 通知详情能够正常显示，不受标记已读功能的影响
2. 不再调用标记已读API，避免403错误
3. 代码逻辑更简洁，专注于获取和显示通知详情

## 技术要点

1. 移除不需要的功能逻辑
2. 简化代码，提高可读性和可维护性
3. 确保核心功能的稳定性
4. 遵循用户需求，不实现不需要的功能
