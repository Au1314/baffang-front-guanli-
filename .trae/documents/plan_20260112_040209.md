# 修复响应呼叫列表显示问题方案

## 1. 问题分析
- 从代码检查来看，`fetchPendingEmergencyList` 函数中已经有了 `pendingEmergencyList.value = listData` 的赋值逻辑
- 但从用户提供的API响应截图来看，API返回的格式是 `{code: 200, data: {...}}`
- 问题可能出在 `request.get` 方法的返回值上，它可能已经将响应处理为直接返回 `response.data`
- 导致条件判断 `if (response && response.code === 200 && response.data)` 失败，`listData` 仍然是空数组

## 2. 实现步骤

### 2.1 修改 `fetchPendingEmergencyList` 函数
- 位置：`Emergency.vue` 中的 `fetchPendingEmergencyList` 函数
- 功能：调整响应数据处理逻辑，适应 `request.get` 方法的实际返回格式
- 实现：
  ```javascript
  const fetchPendingEmergencyList = async () => {
    try {
      emergencyListLoading.value = true
      
      if (!currentLocation.value) {
        // 如果还没有位置信息，先获取位置
        getCurrentLocation()
        return
      }
      
      // 构建请求参数，前4个参数必须传
      const params = {
        pageNum: 1,
        pageSize: 10,
        longitude: currentLocation.value.longitude,
        latitude: currentLocation.value.latitude
      }
      
      // 可选参数：type只有在有值时才传递
      if (emergencyFilter.type !== null && emergencyFilter.type !== undefined) {
        params.type = emergencyFilter.type
      }
      
      // 可选参数：maxDistance只有在有值时才传递
      if (emergencyFilter.maxDistance !== null && emergencyFilter.maxDistance !== undefined) {
        params.maxDistance = emergencyFilter.maxDistance
      }
      
      const response = await authApi.getPendingEmergencyCalls(params)
      
      // 优化数据处理逻辑，适应实际的API响应格式
      let listData = []
      
      // 检查response是否直接包含list字段（即request.get已处理为response.data）
      if (response && response.list) {
        // 如果response直接包含list字段，说明request.get已处理为response.data
        listData = response.list || []
      } 
      // 否则检查是否为完整的响应格式 {code: 200, data: {...}}
      else if (response && response.code === 200 && response.data) {
        listData = response.data.list || []
      } 
      else {
        console.error('API响应格式错误:', response)
      }
      
      // 按照distance字段升序排序，确保最近的呼叫显示在最前面
      listData.sort((a, b) => a.distance - b.distance)
      
      // 更新列表数据
      pendingEmergencyList.value = listData
      
    } catch (error) {
      console.error('获取待处理紧急呼叫列表失败:', error)
      ElMessage.error('获取待处理紧急呼叫列表失败')
      // 确保列表为空，避免显示错误数据
      pendingEmergencyList.value = []
    } finally {
      emergencyListLoading.value = false
    }
  };
  ```

## 3. 预期效果
- 成功获取待响应呼叫列表
- 列表按照距离从小到大排序
- 显示完整的呼叫信息，包括距离、位置、时间等
- 不再显示空列表

## 4. 注意事项
- 确保响应数据处理逻辑能够适应不同的响应格式
- 保留了距离排序功能，确保最近的呼叫显示在最前面
- 保持了完善的错误处理逻辑
