# 修复修改管理员个人信息功能

## 问题分析

当前实现的问题在于头像上传流程不正确：
1. `el-upload` 组件设置了 `action="#"` 和 `auto-upload="true"`
2. 当用户选择图片后，组件会先发送一个无效的 POST 请求到 `#`
3. 然后才调用 `handleAvatarSuccess` 方法，在该方法中调用真正的上传 API
4. 这种流程会导致不必要的网络请求和可能的错误

## 解决方案

修改头像上传流程，采用手动上传的方式：

1. **修改 `el-upload` 组件配置**：
   - 设置 `auto-upload="false"`，禁用自动上传
   - 添加 `@change` 事件监听，处理文件选择
   - 移除或修改 `action` 属性
   - 移除 `:on-success` 事件监听，改为在 `@change` 事件中处理上传

2. **修改上传逻辑**：
   - 添加 `handleAvatarChange` 方法，处理文件选择事件
   - 在该方法中调用 `authApi.uploadAvatar` 上传图片
   - 上传成功后，将返回的 URL 保存到 `editForm.avatar`
   - 移除 `handleAvatarSuccess` 方法或修改其实现

3. **保持其他逻辑不变**：
   - `saveProfile` 方法的实现是正确的，会将 `name` 和 `avatar` 传递给 `updateProfile` API
   - 头像上传前的验证逻辑保持不变

## 具体实现步骤

1. **修改 `Profile.vue` 中的 `el-upload` 组件配置**：
   ```vue
   <el-upload
     class="avatar-uploader"
     :show-file-list="false"
     :before-upload="beforeAvatarUpload"
     :auto-upload="false"
     @change="handleAvatarChange"
     ref="avatarUploadRef"
   >
   ```

2. **添加 `handleAvatarChange` 方法**：
   ```javascript
   const handleAvatarChange = async (file) => {
     try {
       // 获取选中的文件
       const selectedFile = file.file
       if (!selectedFile) return
       
       // 调用头像上传API
       const uploadResponse = await authApi.uploadAvatar(selectedFile)
       console.log('头像上传API响应:', uploadResponse)
       
       // 保存上传后的头像URL
       editForm.avatar = uploadResponse.data
       ElMessage.success('头像上传成功')
     } catch (error) {
       console.error('头像上传失败:', error)
       ElMessage.error('头像上传失败：' + (error.message || '未知错误'))
     }
   }
   ```

3. **移除 `handleAvatarSuccess` 方法**：
   - 由于不再使用 `:on-success` 事件，该方法可以移除

4. **测试功能**：
   - 测试头像上传功能
   - 测试昵称修改功能
   - 测试两者同时修改的功能

## 预期效果

- 用户选择图片后，会直接调用真正的上传 API
- 不再发送无效的请求到 `#`
- 上传成功后，头像预览会更新
- 点击"保存"按钮后，会将上传后的 URL 传递给 `updateProfile` API
- 修改个人信息功能恢复正常

- 确保上传过程中的错误能够被正确捕获和处理
- 确保用户体验不受影响
