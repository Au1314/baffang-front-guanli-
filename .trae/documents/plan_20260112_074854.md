# 修复紧急响应模块页面切换问题

## 问题分析
根据错误信息，页面切换失败的原因可能是：
1. `Cannot read properties of null (reading 'parentNode')` - Element Plus的el-tab-pane组件在卸载时尝试访问已销毁DOM元素的parentNode属性
2. `Cannot read properties of undefined (reading 'dateRange')` - 异步操作在组件卸载后仍在执行，尝试访问已销毁组件的属性

Element Plus的el-tabs组件默认会销毁当前不活跃的标签页内容，当标签页切换时，如果有异步操作正在执行，这些操作可能会尝试访问已销毁的组件属性，导致错误。

## 解决方案
1. **添加组件挂载状态标志**：添加一个响应式数据`isMounted`，在组件挂载时设置为true，卸载时设置为false
2. **在异步方法中检查组件状态**：在所有异步方法中检查`isMounted`的值，只有当组件已挂载时才执行后续操作
3. **添加组件卸载钩子**：在组件卸载时设置`isMounted`为false，确保所有异步操作能够正确停止
4. **优化异步操作处理**：确保所有异步操作都能正确处理组件卸载的情况

## 具体实现步骤

### 1. 添加组件挂载状态标志
在`script setup`中添加：
```javascript
// 组件挂载状态标志
const isMounted = ref(true)
```

### 2. 添加组件卸载钩子
```javascript
// 组件卸载时设置isMounted为false
onUnmounted(() => {
  isMounted.value = false
})
```

### 3. 在所有异步方法中检查组件状态
在以下方法中添加组件状态检查：
- `fetchPendingEmergencyList`
- `selectEmergency`
- `respondEmergencyCall`
- `markAsHandled`
- `handleEndEmergency`
- `completeEmergency`
- `cancelEmergency`
- `addHandlingLog`
- `fetchManageEmergencyList`
- `fetchEmergencyRecords`
- `fetchMyEmergencyResponses`

### 4. 优化异步操作处理
确保所有异步操作在try-catch块中执行，并在catch块中处理组件卸载的情况

## 预期效果
1. 解决标签页切换时的错误
2. 确保组件能够正确卸载
3. 避免异步操作访问已销毁组件的属性
4. 提高系统的稳定性和可靠性

## 实现细节
- 在每个异步方法的关键位置添加`if (!isMounted.value) return`检查
- 确保在组件卸载时，所有异步操作都能正确停止
- 保持与现有代码的兼容性和一致性
