# 修复故障审核API路径错误

## 1. 问题分析
- **错误现象**：API请求返回403 Forbidden，URL：`http://localhost:6101/api/v1/admin/fault/15/audit`
- **根本原因**：故障审核API使用了错误的路径 `/fault/${id}/audit`
- **正确路径**：根据用户反馈，故障审核与投诉审核使用同一个API：`/complaint/${id}/audit`

## 2. 修复方案
- 修改 `auth.js` 中的 `auditFault` 方法，使其使用与 `auditComplaint` 相同的API路径
- 保持参数结构不变，确保兼容性

## 3. 具体实现步骤

### 3.1 修改 `src/api/auth.js`
1. **修复`auditFault`方法**：将路径从 `/fault/${id}/audit` 改为 `/complaint/${id}/audit`
2. **保持方法签名不变**：确保调用方无需修改
3. **保持参数结构不变**：确保请求体参数正确

## 4. 技术细节

### 4.1 修复前API方法
```javascript
auditFault(data) {
  return request.put(`/fault/${data.id}/audit`, {
    action: data.action,
    opinion: data.opinion,
    rejectReason: data.rejectReason || null,
    priority: data.priority || null
  })
}
```

### 4.2 修复后API方法
```javascript
auditFault(data) {
  return request.put(`/complaint/${data.id}/audit`, {
    action: data.action,
    opinion: data.opinion,
    rejectReason: data.rejectReason || null,
    priority: data.priority || null
  })
}
```

## 5. 预期效果
- 故障审核API使用正确的路径
- 403 Forbidden错误消失
- 故障审核功能正常工作
- 投诉审核功能不受影响

## 6. 测试要点
- 审核故障时API请求是否成功
- 审核投诉时API请求是否成功
- 确保两个功能使用同一个API端点

## 7. 注意事项
- 保持方法签名不变，避免影响调用方
- 保持参数结构不变，确保兼容性
- 修复后两个功能使用同一个API端点，符合服务器端设计
